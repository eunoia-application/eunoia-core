# M5 — Сад с FSRS (план)

> Веха M5 из [ROADMAP.md](ROADMAP.md). Дерево знаний на фронте — это **лицо сада**; оно и тянет M5.
> Статус решений — зафиксированы (см. таблицу внизу). Живой прогресс — в [HANDOFF.md](HANDOFF.md).

## Идея

M4 дал статичное мастерство (`Знаю/Учу/—`). M5 превращает его в **живой SRS**: у каждого known-узла
есть *retrievability* R — вероятность вспомнить прямо сейчас; она падает со временем. Лист дерева
свежий → желтеет → опадает по R. Бэкенд отдаёт **непрерывные сигналы** (точные числа, R, дни
активности, стрик), а маппинг «0–50 = росток / высота = f(грамматика)» — целиком на фронте. Стадии
в контракт не зашиваем.

## Фундамент (из M4)

`garden`-контекст: `Mastery(userId, lexemeId, status)` в Postgres + `MasteryUseCase` + 2 кнопки.
Его расширяем до FSRS-карточки. **Два графа держатся:** FSRS-состояние в Postgres ссылается на
`nodeId` графа Neo4j строкой, без FK.

## Модель данных (Postgres, garden)

| Таблица | Поля | Зачем |
|---|---|---|
| `review_state` | userId, nodeId, **nodeKind** (WORD\|GRAMMAR), status, **stability, difficulty, due, lastReviewed, reps, lapses** | FSRS-карточка (развитие плоской `mastery`) |
| `activity_log` | userId, day, actions | стрики / погода / сезоны |
| `review_history` | userId, nodeId, rating, reviewedAt, S до/после | аналитика + будущая калибровка весов |

## Фазы

### Ф0 — оживить на имеющемся + заложить историю  · контракт → **3.2.0** (additive)

- **Журнал активности** — писать `(userId, day)` на каждое действие мастерства **сразу**, чтобы к Ф2
  была реальная история, а не пустой график.
- **Снапшот `GET /learning/tree`** — одним вызовом: `vocabulary(known/learning/total)` + `topics[]`
  (прогресс по веткам) + `activity(streak, daysActive)`. Фасадный джойн двух графов.
- **Гранулярные листья** — фронт рисует лист по-слову (данные уже есть: статусы блока) → чинит баг
  «ствол без листьев, отметил — без изменений». Птицы/золото — клиентские пороги на реальных числах.

### Ф1 — прогресс грамматики → высота  · контракт → **3.3.0**

- Мастерство на правилах (те же 2 кнопки, `nodeKind=GRAMMAR`); `GET /learning/grammar` + статус
  per-user; `PUT …/grammar/mastery/{id}`; грамматика в снапшоте. Высота = f(грамматика known, взвеш. по CEFR).

### Ф2 — ядро FSRS  · контракт → **4.0.0** (ломающий) — тут вся «жизнь»

- **FSRS-движок** — чистый модуль в `garden-logic` (формулы стабильности/сложности/retrievability,
  дефолтные веса FSRS-5), юнит-тесты по эталонным значениям.
- **Очередь** — `GET /learning/review` (due-карточки на сегодня, развитие `/study`) +
  `POST /learning/review/{id}` `{rating}` → пересчёт S/D/due.
- **retrievability в снапшоте** (buckets fresh/fading/wilting + due) → цвет/увядание/опадание листа,
  плотность кроны. Стрики/сезоны/погода — из `activity_log`.

## Зафиксированные решения

| # | Решение | Выбор | Почему |
|---|---|---|---|
| 1 | Глубина SRS | **Полный FSRS-5** | это и есть смысл M5; сложность заперта в чистом модуле |
| 2 | UX повторения | **2 кнопки** (Забыл→Again, Помню→Good) | в духе минимализма карточки; расширяемо до 4 (Again/Hard/Good/Easy) |
| 3 | Таблица мастерства | **одна `review_state` + `nodeKind`** | слова и грамматика ходят через один FSRS |
| 4 | Порядок | **Ф0 → Ф1 → Ф2** | быстрые победы, чинит баг, копит историю к Ф2 |

## Инварианты

- Покрытие **100%** (JaCoCo), как в auth/user/learning.
- Контракт lockstep `<revision>`; Ф0/Ф1 — additive, Ф2 может ломать `/study` → мажорный бамп.
- Два tx-менеджера (JPA + Neo4j) уже настроены — FSRS чисто в Postgres.
- Веса FSRS — дефолтные; персональная калибровка позже (когда накопится `review_history`).
